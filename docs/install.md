# Install

Windows, Linux and macOS builds exist for x64 (Intel/AMD) and arm64.

**Linux: install with Flatpak (recommended).** It works on every distribution with Flatpak, the runtime comes from Flathub and `flatpak update` brings every new release. One command adds the signed repository of the website and installs the app:

```sh
flatpak install --user https://koeroesi86.github.io/tunelle/repo/tunelle.flatpakref
flatpak run io.github.koeroesi86.Tunelle
```

Opening `https://koeroesi86.github.io/tunelle/repo/tunelle.flatpakref` in the browser (download it, then open the file) does the same through GNOME Software or KDE Discover, and so does the link `flatpak+https://koeroesi86.github.io/tunelle/repo/tunelle.flatpakref` on the website, on systems whose software centre opens it (GNOME Software does, KDE Discover since 2025). To add only the repository, use `flatpak remote-add --user --if-not-exists tunelle https://koeroesi86.github.io/tunelle/repo/tunelle.flatpakrepo`. The repository holds the latest release. A `.flatpak` file from a release has no repository, so it does not update: install it again with the command above.

**Windows: install from the Microsoft Store** [<img src="../site/microsoft-store-badge.svg#gh-light-mode-only" alt="Get it from Microsoft" height="44" align="middle"><img src="../site/microsoft-store-badge-light.svg#gh-dark-mode-only" alt="Get it from Microsoft" height="44" align="middle">](https://apps.microsoft.com/detail/9p32skjlncnv) (the Store brings the updates; the library of an installer version is not moved over yet, see #202). **Windows with the installer, macOS and Linux without Flatpak:** download the installer of your system and processor from the [latest release](https://github.com/Koeroesi86/tunelle/releases/latest); the app updates itself on start. On macOS drag the app from the disk image to the Applications folder and start it from there: from the image, or from a folder you can not write to, it does not update (the settings say so). The app is not signed with an Apple Developer ID, so macOS stops the first start: open System Settings, Privacy & Security, click **Open Anyway** below the message about Tunelle and confirm with your password (once; on macOS 14 and older right-click the app and choose Open, or run `xattr -dr com.apple.quarantine /Applications/Tunelle.app`). It then updates itself on start, and macOS may ask again for access to your music folders after an update. The Linux AppImage is built on Ubuntu 22.04 and runs on that or any newer distribution (glibc 2.35 or newer). Installed with [AM](https://github.com/ivan-hc/AM) (`am -i tunelle`) it updates with `am -u tunelle` and not by itself, and so does an AppImage in a folder you can not write to (the settings say so). On Linux the downloaded AppImage has to be made executable first: `chmod +x Tunelle-<version>-<arch>.AppImage`, then `./Tunelle-<version>-<arch>.AppImage` (or tick "Allow executing as a program" in the file manager). It needs FUSE 3: the kernel support and a `fusermount3` helper, which the `fuse3` package provides and desktop installs have. Without FUSE it runs with `APPIMAGE_EXTRACT_AND_RUN=1 ./Tunelle-<version>-<arch>.AppImage`. v26.10.2 and older also need FUSE 2 (`sudo dnf install fuse-libs` on Fedora, `sudo apt install libfuse2t64` on Ubuntu 24.04); without it nothing opens and the reason only shows when the AppImage is started from a terminal.
