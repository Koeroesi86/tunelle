# Tunelle

Electron lossless audio player: main process in `electron/` (TypeScript, SQLite with `migrations/`), renderer in `client/` (React, Redux), build scripts in `scripts/`. The repository is a single package; the default branch is `master` and every change goes through a pull request.

## Checks

CI (`.github/workflows/`: `test.yml`, `dist.yml`, wired together by `pr-checks.yml` for pull requests and `build.yml` for `master`) runs these in this order: 1, 2, 3 and 6 once on Linux (the `static` job of `test.yml`), then the rest on Linux, macOS and Windows (the `test` job, which needs `static`, runs 4, 5 and the build of 7):

1. `npm run lint` (ESLint with Prettier; fix with `npm run lint:fix`, not `prettier --write`)
2. `npm run fallow` (dead code, unused dependencies and stale suppressions fail; complexity and duplication are reported)
3. `npm run typecheck`
4. `npm run test:coverage` (Vitest with coverage thresholds in `vitest.config.ts`, `--project backend` or `--project frontend` for one side with `npm test`)
5. `npm run test:e2e` (Playwright in `e2e/`, run by `test.yml` on every system, after the build, with the Playwright report kept as an artifact: it starts the built `out/`, so `npm run build` first, and measures the audio the app sends out, see Testing the app)
6. `npm run security:electron` (Electronegativity on `electron/`; fails on a finding that is not in `electronegativity-baseline.json`, `node scripts/security-scan.js --update` after fixing one)
7. `npm run build`, then `npm run dist`, `npm run check:dist` (nothing that must not ship is in the package) and `npm run smoke:packaged` (the packaged app opens and answers; needs a display, `xvfb-run` on a headless Linux; `npm run smoke` does the same for `out/`)

Pull requests also run `fallow audit --base` (findings of the changed files), CodeQL, dependency review (high severity, GPL/AGPL licences denied) and OSV.

Pull requests with auto-merge on are rebased onto `master` one at a time, the one whose auto-merge was enabled first (`rebase-auto-merge.yml`, `scripts/rebase-auto-merge.js`), as `master` requires up to date branches. It pushes with the `GH_REBASE_TOKEN` secret, as a push with `GITHUB_TOKEN` starts no checks.

Releases come from `release.yml`: Monday and Thursday 06:00 UTC and by hand, from `master` only. A scheduled run skips when only docs or `.github/` changed since the latest `vYY.M.N` tag. The version is `YY.M.<run number>` (`scripts/version.js`, stamped into `package.json` in the packaging job; never edit `version` by hand, no zero padded month and no prerelease part, electron-updater would take it for a channel), the plan job refuses a version that is not greater than the latest tag, and `release.yml` must not be renamed or recreated (its run number would restart), and the published release is what installed apps update from. A release goes to the Microsoft Store through `store.yml`: `release.yml` calls it after every release it publishes, it runs weekly (Wednesday) for the latest release, and by hand it takes the tag of a release (`workflow_dispatch`; without `commit` it only makes the draft, which is not changed in Partner Center, as a submission made through the API is changed only through the API, but deleted there before the run with `commit`). An automatic run commits; it skips quietly when a submission is in certification or the release is not greater than the version in the Store, and fails when a draft or a failed submission is still there (`decide` of `scripts/store-submission.js`). The secrets are in the environment `microsoft-store` (limited to `master`, with no reviewer: an automatic run starts by itself); it bundles the two `.appx`, since `msstore` takes no `.appx`, and sets the same generic release notes in the draft (`RELEASE_NOTES` of the workflow, and one for each other language of the listing, `RELEASE_NOTES_HU`). `TUNELLE_NO_UPDATE=1` turns the updater off and `TUNELLE_RADIO_DIRECTORY=<url>` replaces the station directory (the smoke tests set both, the second to a station of their own), and `TUNELLE_APP_DATA=<folder>` replaces the app data folder, where the library lives (the end to end tests set it to the profile of the run: on macOS and Windows the app data folder does not follow `HOME`, and a test would use the library of the user).

`node scripts/verify.js` runs 1, 2, 3, 4, 6 and the build of 7 in order and prints only the end of the failed check. A SessionStart hook puts Node 24 of nvm on `PATH` for Claude.

## Guards

Claude Code hooks (`.claude/hooks/`, wired in `.claude/settings.json`, tested in `scripts/claude-hooks.test.js`) block what the rules below forbid: `--no-verify`, `prettier --write`, `continue-on-error`, renaming `release.yml`, pushing to `master`, editing `version` of `package.json` or a migration that has shipped. `git push` and `gh pr create` run lint and typecheck first. `scripts/workflows.test.js` checks the workflow rules, and `pr-description.yml` fails a pull request without **Not verified:**.

## Conventions

- Testing the app (`e2e/`, Playwright with `_electron`, `npm run test:e2e` after `npm run build`): `e2e/app.ts` starts `out/` on a clean profile (a second `start()` in a test is a restart on the same profile) with the fake station directory and the generated library of `e2e/library.ts`, whose tracks are sines of known pitch (`writeFlac({ frequency })`). The window runs with `--disable-audio-output`, and `e2e/audio-probe.ts`, added before the page loads, taps what reaches the destination of the audio context, stamped with the audio clock: assert on pitch, level and silence with `e2e/audio.ts` (`expectTone`, `expectSilence`, `levelNow`, `longestGap`), never on a sleep. Select by the English text of `locales/en.json` and `navigate()` for the sidebar (pages stay mounted, so a text can be on a hidden page too: `filter({ visible: true })`). Anything that differs by system (macOS keeps the app open without a window) is branched on `process.platform` in the test, with the reason.
- The renderer reaches the main process data (library, covers, audio, stations) and the page itself through the `tunelle://app` protocol (`electron/tunelleProtocol.ts`, URLs from `client/local-url.ts`), not through a port. A handler never throws into the main process: an error of a stream ends that stream (`pipeline`, not `pipe`), as an unhandled one opens a blocking error dialog.
- A test next to the code (`name.test.ts`) that fails without the change; no fixed sleeps.
- The code of the app does not take a parameter, an option or a default only so that a test can replace it (`fetcher = fetch`, `now = Date.now`, `pause`, `random`, `gap`, a date that no caller passes, or a fallback for when Electron is not there): it calls `fetch`, `Date.now()`, `setTimeout`, `Math.random` and `utilityProcess` itself, and the test replaces the global (`vi.stubGlobal('fetch', …)`, `vi.useFakeTimers({ toFake: ['Date', 'setTimeout'] })` with `vi.setSystemTime`, `vi.spyOn(Math, 'random')`) or the module (`vi.mock('electron')`; the backend tests get a fake `utilityProcess` from `electron/test-utility-process.ts`). A wait is a `setTimeout` promise, as the fake timers do not cover `timers/promises`. A parameter that the app passes, or that the user sets (a `TUNELLE_` variable), is not a test seam.
- A new migration goes in `migrations/` as `NNN-name.sql` with the next number; it runs once per library (the number is stored as `PRAGMA user_version`), so it may `ALTER TABLE`. Do not edit one that has shipped (`electron/migrations.checksums.test.ts` fails on it; a new migration gets its line in `electron/migrations-checksums.json`). Numbers start at 1 with no gap. A migration runs in a transaction, so it cannot change `PRAGMA foreign_keys`. The library is copied to `library.sqlite.v<N>.bak` before pending migrations run, and a library from a newer app is refused. `001` to `003` ran on every start before the number was stored, so they stay safe to run again.
- User-facing text goes in `locales/en.json` (the complete source of truth) and is shown with `useTranslation()` in the renderer or `getMainTranslator()` in `electron/`, never written into a component; a new language is a `locales/<tag>.json` that is added to `locales/index.ts`, and a key it lacks shows the English text.
- No `any` or casts; fallow suppressions need a reason.
- Workflow changes: actions stay on the major versions already used, with minimal `permissions`.
- The website (`site/`, plain HTML and CSS, `npm run site` shows it) describes the app, so a change that adds, removes or visibly changes a feature (a page, the player bar, radio, platform support, install steps) updates the matching section of `site/index.html` in the same pull request, and the screenshots in `site/screenshots/` when what they show changed (retake them, do not edit them). `npm run build` and then `npm run screenshots` retakes them (`npm run screenshots -- -g songs` takes one; `SCREENSHOTS_OUT=<folder>` writes elsewhere; Linux draws headless and needs no display, Windows and macOS need their desktop): they are taken with the Playwright setup of `e2e/` (the `screenshots` project, `e2e/screenshots/scenes.shots.ts`), the same pictures every time, from made-up data only, which `scripts/screenshot-fixtures.js` writes (generated tagged FLAC files with drawn covers, no real artists, covers or stations; a fake station directory through `TUNELLE_RADIO_DIRECTORY` whose stream names its cover in `StreamUrl`, otherwise the app looks one up online and may show someone else's art) in a clean profile (`HOME` and `XDG_CONFIG_HOME`), English, reduced motion, the colour scheme of the system, 1360×850, the pointer parked off the page, saved as WebP. A new picture is a test in `e2e/screenshots/scenes.shots.ts` (the steps that click through the app, with the clock of the player held where the picture shows it, ending in `capture(page, name)`), and the file it writes goes into `site/index.html`. Keep the Linux install steps in the README and on the page the same.
